오늘 저녁 iQ 3 시험 — Navi 진단 0.5 / Open Headunit 3.3.0
예상 40~60분. GPS 수신과 차량 이동은 필요 없습니다.

0. 출발 전 준비
- 내비 SD카드 NaviTest에 NaviDiagnostic-0.5.apk, OpenHeadunit-3.3.0.apk가 있는지 확인합니다.
- Z Flip7에는 NaviSender-0.1.apk(기존 미러링 송신 앱)를 설치합니다.
- 휴대폰의 Android Auto와 네이버지도를 준비합니다. 네이버지도는 Google Play에서 설치한 버전을 사용합니다.
- 휴대폰 설정 검색에서 ‘Android Auto’를 열어 처음 실행 안내를 마칩니다.
- 유선도 시험한다면 USB-A → USB-C 데이터 케이블을 준비합니다. 충전 전용 케이블은 연결되지 않습니다.
- 차는 움직이지 않는 상태에서 시험합니다. 기어 전환 때는 브레이크를 계속 유지합니다.

1. 내비 앱 설치와 기본 복귀 확인 — 약 3분
1) 기존 파일 관리자로 NaviTest/NaviDiagnostic-0.5.apk를 열어 업데이트합니다. 기존 앱 삭제는 필요 없습니다.
2) NaviTest/OpenHeadunit-3.3.0.apk를 새로 설치합니다. 이 앱은 내비에 설치합니다.
3) Navi 진단 제목의 0.5를 확인합니다. ‘오늘 시험 / Android Auto’를 엽니다.
4) ‘파인 홈’이 열리는지 확인하고 다시 Navi 진단으로 돌아옵니다.
5) 평소처럼 완전 재부팅했을 때 우리 앱이 시작되는지 확인합니다.
기록: 앱 업데이트 / 부팅 자동 실행 = 통과 또는 실패.

2. 핫스팟 최초 연결·기억 — 약 5분
1) 휴대폰 모바일 핫스팟을 켭니다. 내비에서 이름이 보이지 않으면 2.4 GHz / WPA2 옵션으로 시험합니다.
2) 내비 ‘Wi-Fi 관리’ → ‘Wi-Fi 설정 열기’. 열리지 않으면 ‘파인 연결 설정’.
3) 휴대폰 핫스팟을 선택하고 비밀번호를 입력합니다.
4) 우리 앱으로 돌아와 연결 이름과 IP가 표시되는지 확인합니다.
5) ‘현재 Wi-Fi 기억’을 누릅니다. 부팅 시 기억한 Wi-Fi 찾기가 켜집니다.
6) 핫스팟을 잠시 껐다 켜고 ‘다시 연결’로 실제 연결되는지 봅니다.
기록: Wi-Fi 연결 / 기억 / 수동 재연결.
막히면: 오류 화면을 기록하고, USB 케이블이 있으면 5번의 유선 Android Auto 시험으로 넘어갑니다.

3. 부팅 자동 연결과 실패 종료 — 약 4분
1) 핫스팟을 켠 채 내비를 완전 재부팅합니다. 1분 안에 실제 연결 이름/IP가 나타나는지 봅니다.
2) 핫스팟을 끈 채 완전 재부팅합니다. 약 1분 뒤 우리 앱의 연결 시도가 종료되는지 봅니다.
3) 핫스팟을 다시 켜고 ‘다시 연결’로 복구합니다.
빠른 재시동/절전 복귀는 완전 부팅 알림이 없을 수 있습니다. 이 경우 ‘다시 연결’을 사용하고 메모합니다.
기록: Wi-Fi 부팅 연결 / 1분 종료.

4. 기존 미러링 시험 — 10~15분
1) 내비 ‘기존 미러링’ → ‘연결 대기’. 내비 IP와 연결 코드를 확인합니다.
2) 휴대폰 Navi 화면 전송 앱에 그 내비 IP와 코드를 입력하고 화면 공유를 승인합니다.
3) 휴대폰에서 네이버지도를 엽니다. 가로 화면을 기준으로 내비에 표시되는지 확인합니다.
4) 10분 동안 화면이 갱신되는지 봅니다. 목표는 표시 10 fps 이상, 체감 지연 0.5초 이내입니다.
   화면의 fps는 참고값입니다. 정밀 지연 측정이 어렵다면 체감 지연이라고 적습니다.
5) 휴대폰 회전과 앱 전환을 시험합니다. 휴대폰 잠금/공유 중지 때 내비의 오래된 지도 화면이 가려지는지 봅니다.
   잠금 후에는 휴대폰에서 새로 화면 공유를 승인해야 합니다.
6) 공유를 다시 시작하고 R/D 카메라 전환을 3회씩 확인합니다. 카메라가 가려지지 않고 돌아온 뒤 최신 화면이 재개되는지 봅니다.
7) 휴대폰에서 공유를 중지하고 내비의 미러링 화면을 닫습니다.
기록: 기존 미러링 10분 / 회전 / 공유 중지, 미러링 중 R·D 카메라 / 복귀.
이 방식에서는 내비를 터치해 휴대폰 지도를 조작할 수 없습니다.

5. Open Headunit 최초 설정 — 약 3분
1) ‘오늘 시험’의 Open Headunit 버튼을 눌러 초기 안내를 마칩니다.
2) 연결 방식은 무선이면 Headunit Server, 케이블이면 USB를 선택합니다. Self Mode는 선택하지 않습니다.
3) 표시 설정에서 해상도 480p(800×480), 비디오 코덱 H.264, 프레임률 30 fps를 기준으로 설정합니다.
   DPI는 자동/권장값으로 시작합니다. 글자가 너무 작으면 나중에 조절합니다.
4) 자동 시작(부팅·화면 켜짐·Wi-Fi 등)은 끈 상태로 시험합니다. 부팅 진입은 우리 앱이 담당합니다.
5) 오디오 수신(Audio Sink)은 첫 시험에서 끄고 휴대폰 출력으로 확인합니다.
   이후 필요하면 켜서 내비 스피커 출력을 별도 확인하고 결과에 출력 위치를 적습니다.
6) ‘다른 앱 위에 표시’는 이번 수동 연결 시험에서는 허용하지 않고 건너뜁니다. 초기 설정 중 선택 화면이 있으면 필요한 USB/네트워크 권한을 허용합니다.
설정 이름과 위치는 언어에 따라 조금 다를 수 있습니다. 직접 변경한 설정은 사진을 남겨 주세요.

6A. Android Auto 무선 연결 — 핫스팟 사용
1) 내비가 휴대폰 핫스팟에 연결된 상태인지 확인합니다.
2) 휴대폰 설정 → Android Auto → 아래쪽 버전(버전 및 권한 정보)을 10회 눌러 개발자 설정을 활성화합니다.
3) 오른쪽 위 ⋮ 메뉴에서 ‘헤드 유닛 서버 시작(Start headunit server)’을 누릅니다.
   일반 휴대폰 USB 디버깅을 켜는 절차와 다릅니다.
4) 내비 ‘오늘 시험’ → ‘② AA 연결’ → ‘핫스팟 주소 가져오기’를 누릅니다.
   이 주소는 휴대폰의 주소입니다. 4번 미러링에서 휴대폰에 넣었던 내비 주소와 반대입니다.
5) ‘AA 연결 요청’을 누릅니다. 휴대폰에 연결 안내가 나오면 직접 확인합니다.
6) Android Auto 홈/앱 목록이 나오고 네이버지도를 열 수 있으면 연결 성공입니다.
‘서버 확인’ 버튼은 연결이 안 될 때 쓰는 보조 진단입니다. TCP 응답만으로 Android Auto 성공은 아닙니다.
막히면: Open Headunit의 Wi-Fi/Headunit Server 화면에서 휴대폰 주소를 직접 입력해 봅니다.
그래도 안 되면 휴대폰 서버를 중지·시작하고 한 번 재시도합니다. 5분 이상 같은 곳에서 반복하지 말고 오류를 기록합니다.
집 공유기를 사용할 때: ‘핫스팟 주소 가져오기’를 쓰지 않고 휴대폰 Wi-Fi 상세정보의 IP를 직접 입력합니다.

6B. Android Auto 유선 연결 — 케이블이 있을 때
무선에 실패하거나 비교하고 싶을 때만 진행합니다. 유선은 Wi-Fi가 없어도 시험할 수 있습니다.
1) 무선 연결이 실행 중이면 먼저 종료합니다. 내비에서 Open Headunit을 엽니다.
2) 내비 USB-A 데이터 포트와 휴대폰 USB-C를 데이터 케이블로 연결합니다.
3) 휴대폰 잠금을 풀고 USB 옵션이 나오면 Android Auto/파일 전송 항목을 선택합니다.
4) Open Headunit의 USB 버튼을 누르고 휴대폰을 선택합니다. USB 접근 안내가 나오면 허용합니다.
5) 휴대폰 Android Auto 안내를 마친 뒤 내비에 앱 목록이 나오는지 봅니다.
막히면: 충전만 되는지, USB 목록에 휴대폰이 있는지 구분해서 기록합니다. 케이블을 한 번 다시 연결해 봅니다.
기록: Android Auto 연결 / 지도 터치. 메모에 무선·유선 중 성공한 방식을 적습니다.

7. Android Auto 사용과 카메라 공존 — 10~15분
1) 네이버지도에서 내비 화면을 터치해 지도 이동/버튼 반응을 확인합니다. 목적지나 개인 정보는 기록할 필요 없습니다.
2) 지원되는 음악 앱이 있으면 열어 재생·일시정지와 소리 출력 위치를 확인합니다.
3) 연결을 10분 유지하며 멈춤·깜빡임·끊김을 봅니다.
4) R/D 카메라 전환을 각각 3회 확인합니다. Android Auto가 카메라 위에 올라오는지, 돌아왔을 때 최신 지도가 나오는지 봅니다.
5) 핫스팟 끄기 또는 케이블 분리로 연결을 끊습니다. 오래된 지도 화면이 현재 화면처럼 남는지 확인합니다.
6) 다시 연결하고, 마지막에 Android Auto를 종료한 뒤 우리 앱/파인 홈으로 돌아옵니다.
   우리 앱의 ‘AA 종료 요청’으로도 종료를 요청할 수 있습니다.
기록: Android Auto 10분 / 오디오, 카메라 / 복귀, 끊김 / 재연결 / 파인 홈.
카메라가 가려지거나 복귀가 실패하면 해당 결과를 실패로 기록하고 그 상태로 사용을 계속하지 않습니다.

8. 결과 정리 — 약 2분
‘오늘 시험’ → ‘③ 결과 기록’에서 각 항목을 눌러 미확인/통과/실패/건너뜀을 선택합니다.
메모에 아래만 적어도 다음 수정에 충분합니다.
- 미러링 성공 여부 / 표시 fps / 체감 지연
- Android Auto 무선 또는 유선 성공 여부
- 지도 터치 여부 / 소리가 나온 곳
- R/D 카메라가 가려졌는지 / 앱 복귀까지 걸린 시간
- 실패한 단계와 정확한 오류 문구
‘메모 저장’을 누르면 내비 안에 보관됩니다. ‘결과 파일 저장’에서 SD카드를 고를 수 있으면 파일로 저장합니다.
파일 저장 화면이 없다면 결과 화면과 오류 화면을 휴대폰으로 촬영해 주세요.
GPS는 오늘의 통과 조건에 포함하지 않습니다.
